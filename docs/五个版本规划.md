# 潮线后续五个版本规划

调研对象：Trello、Asana、ClickUp 与板栗看板。它们共同验证了商用看板工具的高频能力：
自定义字段、规则自动化、重复任务、提醒、工时/负载、报表、卡片封面与列表约束。
潮线坚持「本地优先、个人使用」定位，不引入多人协作、评论、@成员与云端依赖，
只吸收能提升个人项目掌控力的部分。

参考：
- [Trello 功能与限制综述（ClickUp）](https://clickup.com/learn/topic/project-management/tools/trello/)
- [Asana 工作管理功能](https://asana.com/zh-tw/product/use-asana)
- [ClickUp 项目/任务能力对比](https://ones.com/blog/ones-project-management/best-project-management-2026/)
- [板栗看板「自定义字段」](https://banlikanban.com/help/cutom-filed.html)
- [板栗看板企业版能力](https://banlikanban.com/help/teampay-handbook.html)

## 总原则

- **本地优先**：数据继续保存在本机 SQLite；联网功能必须可关闭、失败可降级。
- **不做团队协作**：不做成员、权限、评论、通知他人；只做「一个人的项目系统」。
- **先结构后智能**：先让字段、视图、规则可控，再叠加提醒和报表。
- **每版可回滚**：数据库迁移幂等；备份包含全部新实体；旧备份可恢复。
- **每个版本一个主线**，避免功能堆叠导致看板变重。

## V0.9 需求文档一键拆解（已完成）

**目标**：别人给的需求文档，一键变成看板里的任务与子任务，并控制拆解深度。

- 粘贴需求文本 / 读取 `.md`、`.txt` 文件；按 Markdown 标题、编号、列表解析层级
- 自定义拆解深度（1–4 层）：顶层成为看板任务，子层成为子任务并保留缩进/编号语义
- 预览拆解结果，选择目标看板与列表，确认后批量生成
- 支持「一个任务承载子任务」和「按章节拆成多个任务」两种模式
- 保留原文段落作为任务描述；同名任务提示避免重复
- 解析过程完全本地、无需 AI 服务；后续可接入本地模型增强

验收：常见需求文档层级解析正确；深度设置生效；生成后任务/子任务可编辑；不影响已有看板数据。

落地情况（V0.9.0）：

- 新增「需求拆解」页面（`/#/requirements`），侧边栏位于「模板中心」下方
- 解析器 `src/lib/requirementParser.ts`：Markdown 标题、编号列表（`1.` / `1.1.`）、缩进列表、普通段落与代码块；唯一一级标题自动识别为文档标题并上提一层
- 拆解计划 `src/lib/requirementPlan.ts`：深度 1–4 层，两种拆解方式；超出深度的内容折叠进任务描述而非丢弃；同名任务与看板已有任务比对标记
- 桌面端新增 `pick_requirement_file` 命令走原生文件对话框，浏览器开发态降级为隐藏 file input
- 只新增任务与子任务，不改动看板已有数据；解析与拆解全程本地，不经过 AI 服务
- 单测：`requirementParser.test.ts` 8 项 + `requirementPlan.test.ts` 8 项

## V0.10 桌面软件使用统计（已完成，2026-10）

**目标**：自动记录当前活跃桌面软件的使用时长，找出时间花在哪。

- 潮线运行期间后台采样前台窗口；用户空闲（无操作）时不记录
- 只统计当前活跃的前台软件，不累计后台进程
- 应用清单可选：默认记录发现的所有应用，用户可勾选纳入统计的软件清单
- 按今天/本周/最近 7 天/自定义区间查看各软件时长、占比与趋势
- 一键暂停统计、清空本地记录；数据只存本机，不上传
- 需要 Windows 原生 API；无网络权限

验收：切换前台应用后时长准确累加；空闲不增长；取消勾选的软件不计入统计；暂停/清空生效；数据只存本机，不上传。

落地情况（V0.10.0）：

- schema v11：新增 `usage_apps` / `usage_daily` / `usage_settings` 三张表，用量数据只写入本机 SQLite
- 桌面端运行期间后台线程每 1 秒读取一次 Windows 前台窗口，活跃前台应用的时长按整秒累计、每 10 秒落库并按天归档；该线程随应用进程退出而结束，不单独常驻
- 前台切换时把该段未累计的零头结算给旧应用（结算量钳制在 1–60 秒），长时间停留在同一应用不会被上限截断
- 采样线程被系统挂起（休眠后恢复、长时间抢不到 CPU）导致两轮间隔超过 60 秒时，这段停顿时长整段丢弃并重新起算，不会凭空给应用加上几小时
- 空闲判定阈值默认 300 秒，可在 30–3600 秒之间配置；空闲期间不累计时长
- 应用清单默认全部纳入统计，可逐个取消勾选；取消勾选的应用不计入时长与占比
- 区间查看：今天 / 本周 / 最近 7 天 / 自定义区间（不传区间时按今天），展示各软件时长、占比与按天趋势
- 一键暂停统计与清空本地记录均即时生效；清空只清除已记录的时长，应用清单与设置保留；全程无网络请求，不上传任何数据
- 新增 6 个前后端命令：`get_usage_overview` / `get_usage_apps` / `set_usage_app_included` / `get_usage_settings` / `set_usage_settings` / `clear_usage_records`
- 前端新增「使用统计」页面（路由 `/usage`，侧边栏「使用统计」入口紧跟「仪表盘」）：时长排行、每日趋势、区间切换、暂停/继续、空闲阈值设置、应用清单勾选与二次确认清空
- 浏览器预览模式没有采样器：页面顶部提示「本功能需要桌面端运行」，统计与清单展示空数据占位
- 单测：`src/lib/usage.test.ts` 36 项（时长格式化、占比、区间换算与跨月跨年、趋势补齐、阈值钳制）；`src-tauri/src/usage.rs` 12 项（应用名归一化、按天累计、区间筛选与补天、取消勾选不计入、清单排序、清空保留清单与设置、设置字段级更新与阈值越界报错、缺省今天与非法日期、采样线程与设置共享、区间枚举、采样被挂起时丢弃停顿时长）

## V0.11 自动化与提醒（已完成）

**目标**：把重复劳动和「别忘了」交给本地规则。

- 重复任务：每天/每周/每月/自定义间隔；完成后生成下一次
- 本地规则：任务移动到某列/被完成时，自动设置日期、优先级、标签或子任务
- 本地提醒：到期/逾期/每日摘要，使用系统通知；提醒时间可配置
- 活动日志：记录任务字段变化，支持按任务查看最近活动
- 所有自动化默认关闭，逐条启用；失败不阻塞主流程

验收：重复任务正确滚动；规则只在本地执行；提醒可关闭不打扰。

### 落地情况

- 数据库 schema v12：新增 `recurrences` / `recurrence_runs` / `automation_rules` / `card_activity` / `notification_settings` / `notification_deliveries` 六张表，`cards` 增加 `recurrence_id` / `generated_from_id`
- 重复任务：每天、每周（可选星期）、每月（短月收敛到月末）、自定义间隔天数；完成后克隆原任务生成下一次未完成任务，`recurrence_runs` 主键 `(recurrence_id, completed_card_id)` 保证同一次完成不会重复生成
- 本地规则：只有 `move_to_list` 与 `complete` 两种触发，动作限于设置/清除截止日期、设置优先级、添加标签、追加子任务；`enabled` 默认 0，需要在设置页逐条启用；规则在卡片写入事务内执行，失败只写入 `last_error`，不阻塞任务本身
- 本地提醒：到期 / 逾期 / 每日摘要三个开关，摘要时间与提前天数可配置，默认全部关闭；桌面端走 `tauri-plugin-notification` 系统通知，投递记录按 `(kind, day, card_id)` 去重；浏览器预览模式只保存设置
- 活动日志：卡片创建、修改、移动、完成、删除、恢复与重复生成都留痕，逐字段对比旧值与新值；任务详情底部展示最近活动
- 前端新增 11 个命令：`get_card_activity` / `get_recurrences` / `create_recurrence` / `update_recurrence` / `delete_recurrence` / `get_automation_rules` / `create_automation_rule` / `update_automation_rule` / `delete_automation_rule` / `get_notification_settings` / `set_notification_settings`
- 备份：重复配置、规则与活动日志随 JSON 备份导出与恢复；旧备份缺少这些字段时按空集合处理；提醒设置属设备偏好，不进备份
- 单测：`src/lib/automation.test.ts` 24 项（日期推算含月末收敛与跨年、规则动作校验与叠加、活动日志文案）；`src-tauri/src/automation.rs` 9 项、`src-tauri/src/reminders.rs` 8 项、`src-tauri/src/backup.rs` 2 项

## V0.12 多类型任务关系与跨看板依赖（已完成）

> 本节原先规划的是「时间、负载与洞察分发」。根据 [市场特性调研](市场特性调研-任务与看板管理.md) 与 [路线图](roadmap.md)，
> 优先级调整为：先做「多类型任务关系 + 跨看板依赖」，工时与负载顺延到 V0.15。

**目标**：让任务之间的关联从单一的「前置阻塞」扩展为有语义的关系网，同时打通跨看板的依赖表达。

- 关系类型扩展：`blocks`（前置，沿用原语义）、`relates`（相关）、`duplicates`（重复）
- 数据库：`card_dependencies` 增加 `relation_type` 列，schema 升至 v15，旧库幂等迁移
- 放开跨看板限制：不再要求「只能依赖同一看板内的任务」
- 前端：任务详情的关系区可按类型添加、切换、移除；看板与甘特连线按类型区分样式
- 阻塞判定只认 `blocks`：相关与重复关系不产生阻塞，也不参与循环依赖检测
- 备份兼容：旧备份缺少 `relationType` 时按 `blocks` 处理

同版本下线「使用统计」：与看板工具定位不符，已移除入口与路由并停止后台采样线程。

## 版本节奏与发布要求

- 每个版本：`typecheck` + `vitest` + `cargo test` + Playwright 关键流程 + 截图。
- 数据库变更：`PRAGMA user_version` 递增，新增列/表幂等迁移，备份新旧兼容。
- 安装包：中文向导；先测试「旧版本自定义目录 → 新版本覆盖安装」。
- 版本号与 README、开发计划、安装包同步；构建产物放 `release/`。

## 非目标（继续不做）

多人协作、评论、@成员、通知他人、云端同步、SaaS 订阅、团队权限。
