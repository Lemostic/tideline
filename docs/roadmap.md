# 潮线 tideline 产品路线图（Roadmap）

> 版本：2026-11-01　依据：[市场特性调研-任务与看板管理](市场特性调研-任务与看板管理.md)
>
> 本路线图只收录经过市场调研筛选、且与「本地优先、个人 / 小团队单机使用」定位相容的特性。
> 多人协作、云端同步、账号体系等能力不在规划内，理由见调研报告第五节。

---

## 一、产品定位与取舍原则

潮线是一款**本地优先、开源免费的多视图看板工具**。数据全部存在本机 SQLite 单文件里，不要求账号、不依赖网络、不收集数据。

所有进入路线图的特性都必须满足三条：

1. **提升个人项目掌控力**，而不是为协作场景增加设置负担。
2. **本地可完整实现**，联网能力必须可关闭、失败可降级。
3. **数据留在本机**，不引入需要上传数据的第三方服务。

已下线的特性：桌面软件使用统计（偏离看板工具定位，后台采样已停止，代码与历史数据保留，见第五节）。

## 三、V0.12：多类型任务关系与跨看板依赖（进行中）

**目标**：让任务之间的关联从单一的「前置阻塞」扩展为有语义的关系网，同时打通跨看板的依赖表达。

调研依据：Jira 默认提供 relates to / duplicates / blocks / is blocked by 等多种问题链接类型；Linear 用 relations 区分阻塞与重复；ONES 的跨团队依赖测评把「区分前置、后置、阻塞等类型」列为依赖建模的首要确认点。

### 交付内容

- **三种关系类型**：`blocks`（前置阻塞，沿用现有语义）、`relates`（相关联）、`duplicates`（重复）
- **关系类型在数据库层落地**：`card_dependencies` 增加 `relation_type` 列，schema 升至 v15，旧库幂等迁移
- **跨看板依赖放开**：不再限制「只能依赖同一看板内的任务」，看板集本就是跨看板容器
- **前端表达**：任务详情的关系区可按类型添加、切换、移除；卡片与甘特视图的连线区分类型
- **阻塞判定只认 `blocks`**：`relates` 与 `duplicates` 不产生阻塞状态，不参与循环依赖检测
- **备份兼容**：旧备份文件缺少 `relationType` 时按 `blocks` 处理

### 验收标准

- [ ] 三种关系均可添加、修改类型、移除，并在任务详情中正确显示
- [ ] 只有 `blocks` 关系会让卡片显示「被阻塞」，且阻塞计数正确
- [ ] `relates` / `duplicates` 关系不参与循环依赖判定
- [ ] 可建立跨看板的 `blocks` 关系，卡片在两个看板中都正确显示阻塞状态
- [ ] 数据库升级到 v15 时旧数据完整，旧备份可正常恢复
- [ ] 看板连线与甘特图连线区分关系类型，跨看板关系在各自看板内正常绘制

## 四、V0.13：自定义字段与筛选视图（规划中）

**目标**：让用户能在自己的看板里定义字段结构，并把常用的观察视角固化下来。

调研依据：Trello Standard 档把 Custom Fields 与 Saved searches 列为核心能力；Asana 以自定义字段与 saved views 支撑其数据模型；Notion 的动态过滤排序是数据库引擎的卖点。

### 交付内容

- **自定义字段**：支持「下拉选项」与「数值」两类，覆盖个人工具的真实需求；字段定义按看板隔离
- **字段值存储**：`cards` 增加字段值承载结构，schema 递增，备份新旧兼容
- **与现有标签的关系**：现有 `priority` 是硬编码枚举，自定义字段落地后可作为其泛化路径
- **保存的筛选视图**：把当前筛选条件（关键词 / 完成状态 / 优先级 / 标签）保存为命名视图，看板头部可切换
- **筛选视图与自定义字段联动**：筛选器可按自定义字段值过滤

### 验收标准

- [ ] 可在看板内定义、编辑、删除自定义字段，旧任务自动补默认值
- [ ] 自定义字段值可在任务详情编辑，列表与表格视图正确展示
- [ ] 看板内筛选器可按自定义字段过滤
- [ ] 保存的筛选视图在刷新后保持，可一键切换与删除
- [ ] 自定义字段与筛选视图随备份导出 / 恢复

## 五、V0.14：里程碑、批量编辑扩展与撤销重做（规划中）

**目标**：补上「交付节点」概念，并降低误操作的代价。

调研依据：ONES 把「里程碑和迭代节奏」列为跨团队对齐机制，Jira 用 Version 作为发布单位；所有主流看板都提供批量操作；Trello 有 Undo 按钮。

### 交付内容

- **里程碑实体**：可命名、可设目标日期、可关联一组任务；甘特图用真正的菱形标记替代当前的单日降级渲染
- **批量编辑字段扩展**：在现有「移动列表 / 设置优先级 / 标记完成 / 移入回收站」基础上，增加标签、截止日期、起始日期
- **撤销重做**：覆盖拖拽、批量操作、字段修改等易错操作，回收站只解决「删除」，不解决「改错」

### 验收标准

- [ ] 里程碑可创建、编辑、删除、关联任务，甘特图正确绘制里程碑标记
- [ ] 批量编辑可同时改标签、截止日期与起始日期
- [ ] 撤销 / 重做覆盖拖拽与批量操作，栈深度合理

## 六、V0.15：命令面板与工作负载视图（规划中）

**目标**：降低导航与操作成本，并在个人尺度上呈现精力分配。

调研依据：Linear 的键盘优先是其口碑来源，Notion 的 Cmd+K 全局搜索是其效率核心；Asana 的 Workload 回答「这个人的活会不会爆」，monday.com 横评把资源管理列为 2026 年的关键取舍点。

### 交付内容

- **命令面板**：复用现有 Ctrl+K 搜索弹窗，支持切换视图、打开页面、新建任务、跳转看板、切换主题
- **工作负载视图**：按天 / 周呈现任务量与预估工时分布，标出超载区间（与 V0.12 的工时字段协同）

### 验收标准

- [ ] 命令面板可执行跳转、创建与切换类命令，支持模糊匹配
- [ ] 工作负载视图按区间给出负载分布，超载区间有明确提示

## 七、后续候选（尚未排期）

以下特性在调研中被认可，但工程量或定位契合度需要更多评估，暂不排入具体版本：

- **泳道**：Taiga / WeKan / Jira 都有。潮线看板从一维列布局变为二维，工程量最大，需要先做小范围验证
- **番茄钟与专注模式**：TickTick 把内置番茄钟作为核心卖点。对潮线而言这是唯一能形成差异化的候选——只有潮线能同时回答「这段时间你在 VS Code 写了 40 分钟，但这个任务只记了 25 分钟」，因为 V0.10 已具备 Windows 前台窗口采样能力。前提是使用统计恢复启用
- **附件**：开源工具（Vikunja）的标配能力，个人工具场景下价值中等
- **看板模板与卡片模板分离**：Trello 区分 board template 与 card template，当前模板中心只有看板级模板

## 八、明确不做的能力

以下能力在调研中出现频率很高，但与潮线定位冲突，不进入路线图：

| 能力 | 不做的理由 |
| --- | --- |
| 多人协作（成员 / 评论 / @ / 权限 / 分享） | 价值建立在「有第二个人在用」之上，单机场景只增加设置负担 |
| 云端同步与账号体系 | 直接违背「不用账号、数据只属于你」的主张 |
| 云端 AI 摘要与自动分派 | 需求拆解已刻意做成纯本地解析，引入云端 AI 会让「数据不出本机」失效 |
| 冲刺 / 迭代周期（Cycles / Sprint / 燃尽图） | 多人节奏的产物，「我的任务」按截止日期分桶对个人已够用 |
| 移动端与跨设备 | 桌面端是前提，前台窗口采样等能力绑定 Windows 环境 |

## 九、版本要求

- 每个版本必须通过 `pnpm typecheck`、`pnpm test`、`cargo test` 与 Playwright 关键流程验证
- 数据库变更必须幂等迁移，`PRAGMA user_version` 递增，备份新旧兼容
- 旧版自定义数据目录 → 新版覆盖安装需实测通过
- 版本号与 README、开发计划、安装包校验值同步更新
