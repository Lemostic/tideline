# 子任务升级为真实任务（任务树）设计

- 日期：2026-11-02
- 版本：V0.14.0
- 状态：待评审
- 关联：`docs/开发计划.md`、`docs/更新记录.md`

## 1. 背景与目标

当前子任务是存在 `cards.subtasks` JSON 里的轻量清单项 `{ id, title, done }`，只能勾选完成与删除，无法维护状态、优先级、日期、标签、描述、工时、关系、自定义字段等主任务已有的元数据。

目标：让子任务成为**真正的任务**，与主任务共用同一套任务详情与全部能力，并支持任意层级；同时保证既有行为（看板折叠、进度、统计口径）与旧数据/旧备份的平滑迁移。

### 成功标准

- 子任务拥有与主任务一致的任务详情（除下文明确列出的例外字段），可编辑并持久化。
- 现有子任务数据一键升级，标题、完成状态、顺序不丢；旧 JSON 备份可导入。
- 看板、表格、甘特、日历、我的任务、工作台、仪表盘、看板集、目标、搜索、回收站、自动化、模板、需求拆解在子任务存在时行为明确且不重复计数。
- 桌面端与浏览器预览模式行为一致；schema v18 → v19 幂等迁移；全量测试通过。

### 非目标（本期不做）

- 子任务的拖动排序、把子任务提升为主任务、跨父任务搬移。
- 在看板上把子任务渲染为独立卡片。
- 子任务按重复规则滚动生成。
- 子任务级别的模板。

## 2. 现状

- `Card.subtasks: Subtask[]`，数据库 `cards.subtasks TEXT`（JSON）。
- 使用点：任务详情（勾选/添加/删除/进度）、表格视图第三层缩进、看板卡片进度、甘特条进度、回收站与仪表盘统计、需求拆解 nested 模式、自动化 `append_subtasks`、模板数据、备份。
- 任务详情为居中弹窗 `TaskDrawer`，字段修改即时保存；跨视图统一入口。

## 3. 方案选择

- **方案 A（采用）：`cards.parent_card_id` 自引用。** 子任务即卡片，复用全部字段、命令、关系、自定义字段、活动日志、回收站与备份；扁平快照 + 前端建树。
- 方案 B：独立 `subtask_cards` 表，字段/命令/备份双份维护，长期漂移，放弃。
- 方案 C：保留 JSON 并扩展字段，无法进入其他视图、无关系/自定义字段/回收站，不满足目标，放弃。

## 4. 数据模型（schema v19）

```sql
ALTER TABLE cards ADD COLUMN parent_card_id TEXT REFERENCES cards (id) ON DELETE CASCADE;
CREATE INDEX idx_cards_parent ON cards (parent_card_id);
```

- `parent_card_id IS NULL` = 主任务；非空 = 子任务。层级不限。
- 子任务与父任务**同看板**；`list_id` 跟随父任务（父任务移动列表时同步整棵子树），详情中「所属列表」只读。
- 子任务 `position` 在**同级兄弟**内排序（与主任务在列表内排序互不影响）。
- 子任务不参与「重复任务」：`create_recurrence` 对 `parent_card_id` 非空的卡片直接报错「子任务不支持重复任务」，任务详情隐藏重复入口；已存在的重复配置不受影响。
- 卡片颜色 `accent` 对子任务无意义：详情隐藏该字段，数据保留不读写。
- 删除/恢复：软删除父任务时递归软删全部后代（同一时间戳）；恢复父任务递归恢复后代；子任务单独删除只影响自身子树。彻底删除父任务由外键级联物理删除后代。
- 进度：父任务进度 = **全部后代**中已完成数 / 全部后代数（仅统计未删除任务）；主任务自身 `completed` 仍独立维护，不自动完成。
- 不变量：
  1. `parent_card_id` 必须指向存在的卡片，且父任务与子任务 `board_id` 相同；
  2. 不得自指、不得成环；
  3. 业务层不限制层级；技术上限 100 层（防止脏备份/异常数据），正常 UI 缩进在 6 层后保持固定缩进；
  4. 子任务 `list_id` 必须等于父任务 `list_id`。

### 迁移（v18 → v19，幂等）

对 `cards.subtasks` 非空且 `parent_card_id IS NULL` 的卡片：

1. 按数组顺序为每个清单项创建子卡片：`id = sub_<parent_id>_<index>`、`board_id`/`list_id` 继承父任务、`title` 原样、`completed = done`、`position = index`、`description = ''`、日期/优先级/标签/工时为默认值、`created_at/updated_at = 父任务 updated_at`（或迁移时刻）。
2. 子卡片 `parent_card_id = 父任务 id`；若同 id 已存在则跳过（幂等）。
3. 父任务 `subtasks = '[]'`。
4. 整个迁移在一个事务中完成；失败回滚并返回带「迁移 cards.subtasks 失败」的错误。

旧备份（`cards[].subtasks` 非空、无 `parentCardId`）在导入时执行等价展开：先插入全部卡片，再逐层展开子任务 JSON（子任务内若有嵌套数组则递归，保留原 id 语义）。

## 5. 类型与接口

### 前端类型

```ts
export interface Card {
  // ...既有字段
  parentCardId: string | null;   // 新增
  // subtasks 字段删除；旧备份解析在 backup.ts 内部保留 LegacySubtask
}
export interface NewCardInput { /* ... */ parentCardId?: string | null }
```

新增 `src/lib/taskTree.ts` 纯函数模块（所有视图统一使用，避免散落判断）：

- `childCardsOf(cards)`、`childrenOf(cards, parentId)`、`rootCards(cards)`、`descendantsOf(cards, id)`、`isSubtask(card)`；
- `subtaskProgress(cards, cardId): { done: number; total: number; percent: number }`（全部后代）；
- `breadcrumbOf(cards, cardId): Card[]`（从主任务到当前任务）；
- `buildCardTree(cards)`（表格/详情共用）；
- `depthOf(cards, cardId)`。

### 后端命令

- `NewCardInput` 增加 `parent_card_id: Option<String>`；`create_card`：
  - 校验父任务存在、与 `list_id` 同看板、深度 < 100；
  - `list_id` 必须等于父任务列表（否则报错「子任务必须跟随父任务列表」）；
  - 子任务位置追加到同级末尾；忽略重复配置相关入参。
- `Card` 输出增加 `parentCardId`；`CARD_COLUMNS` / `row_to_card` 相应更新。
- `update_card`：子任务禁止通过 `list_id` 单独换列（报错「子任务不能单独移动列表」）；其余字段正常。
- `move_card`：目标卡片为子任务时报错；移动主任务时在事务内把整棵子树的 `list_id` 同步为目标列表。
- `delete_card` / `restore_card` / `purge_*`：按第 4 节递归语义实现；`delete_card` 对已删除卡片幂等。
- 快照不变（仍然扁平返回活动任务），前端建树。

### 备份

- 导出：卡片新增 `parentCardId`（camelCase），其余字段不变。
- 导入校验新增：`parentCardId` 指向的卡片必须存在于备份中、同看板、无自指/环、深度 ≤ 100；主任务与子任务的 `list_id` 一致性在导入时以父任务为准修正（兼容旧备份）。
- 旧备份展开：`subtasks` 数组非空时按迁移规则生成子卡片；子任务卡片上若还有 `subtasks` 递归展开。
- 备份格式版本保持 `1`（新增字段向后兼容）。

## 6. 任务详情（TaskDrawer）

- 子任务区从「清单」改为「任务树」：缩进展示全部后代，每行含完成勾选、标题、状态/优先级/日期/标签摘要、打开详情、删除；支持就地新增子任务（继承父任务看板/列表/父 id）。
- 点击子任务打开同一套任务详情，顶部面包屑「主任务 › 子任务 › …」，可逐级回溯；关闭弹窗回到原视图。
- 子任务详情字段：状态、优先级、起止日期、标签、Markdown 描述、预估/实际工时、自定义字段、任务关系、最近活动、移入回收站；保留子任务树区块（可继续向下拆）。
- 子任务详情隐藏：卡片颜色、重复任务、所属列表（只读展示父任务列表）。
- 关系：选择器列出主任务与子任务（带父链、排除自身与后代）；看板与甘特上的关系箭头只绘制主任务之间的边，子任务的关系在详情中查看。
- 活动日志：子任务独立记录；父任务的活动区不汇总子任务日志（避免噪音）。

## 7. 视图与统计口径

| 位置 | 口径 |
| --- | --- |
| 看板 | 只渲染主任务；卡片进度按全部后代；列计数只算主任务 |
| 表格 | 主任务行 + 递归子任务行（三层以上继续缩进，6 层后固定缩进）；子任务可勾选，点击打开子任务详情；搜索命中子任务时带父链 |
| 甘特 / 日历 / 筛选 / 保存视图 | 只处理主任务 |
| 我的任务 / 工作台 | 只处理主任务 |
| 仪表盘 | 任务数、完成数、吞吐、年龄等只算主任务；子任务完成率统计全部后代；不做父子重复计数 |
| 看板集 / 目标进度 | 只算主任务；目标关联选择器只列主任务 |
| 全局搜索（Ctrl+K） | 包含子任务，结果显示「父任务 › 子任务」面包屑，回车打开子任务详情 |
| 回收站 | 列出被删除任务（含子任务）；子任务行标注父任务；恢复子任务时一并恢复仍被删除的祖先；彻底删除子任务删除其子树 |
| 模板中心 / 需求拆解 nested / 自动化 append_subtasks | 生成真实子任务卡片，而不是写入 JSON |

## 8. 浏览器预览模式

- `loadLocalDb` 读取旧 `subtasks` JSON 时执行与 Rust 迁移等价的展开（确定性 id `sub_<parentId>_<index>`，展开后把父任务 `subtasks` 置空）；由于 id 确定性，重复读取不会产生重复子任务。
- `localApi` 的 `createCard` / `updateCard` / `moveCard` / `deleteCard` / `restoreCard` / `purgeCard` / 备份导入导出与桌面端保持同一套校验与递归语义。

## 10. 风险与应对

- **迁移数据风险**：迁移在事务内完成，失败回滚并提示先备份；迁移前建议自动导出一次 JSON 备份（可在设置页提示，本期仅在文档说明）。
- **视图回归**：所有跨任务视图必须经 `taskTree` 过滤；用测试锁定「仪表盘/我的任务不重复计数」。
- **软删除递归**：子树删除/恢复与历史数据混合，重点测试幂等与恢复顺序。
- **备份兼容**：旧备份展开与脏数据校验，双端（Rust/TS）一致性测试。
- **性能**：快照全量返回，前端建树 O(n)；任务量小，可接受；避免每行重复计算后代（使用 Map 索引）。
