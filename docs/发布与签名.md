# 发布与代码签名

潮线目前以 **NSIS 安装包 + GitHub Release** 分发。应用内更新检查（V0.6.1）只负责发现新版本并打开发布页，
**不会自动下载或静默安装未签名安装包**。在接入代码签名证书前，这一步由用户手动完成。

## 发布清单

> 约定：**每个版本开发完成、版本号升版并提交之后，必须立即打包**（步骤 3–4），不能只交代码不交安装包。

1. 更新版本号：`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 保持一致。
2. 运行检查：
   ```bash
   pnpm typecheck
   pnpm test
   cargo test --manifest-path src-tauri/Cargo.toml
   ```
3. 构建安装包：
   ```powershell
   pnpm tauri build --bundles nsis
   ```
   产物：`src-tauri/target/release/bundle/nsis/tideline_<版本>_x64-setup.exe`
   复制到发布目录（`release/` 已在 .gitignore 中）：
   ```powershell
   Copy-Item -Force .\src-tauri\target\release\bundle\nsis\tideline_<版本>_x64-setup.exe .\release\tideline-<版本>-win64-setup.exe
   ```
4. 生成 SHA256 并记录：
   ```powershell
   Get-FileHash .\release\tideline-<版本>-win64-setup.exe -Algorithm SHA256
   ```
5. 在 GitHub 创建 **正式 Release**（不要勾选 draft / pre-release），上传安装包；
   标题使用 `v<版本>`，正文写更新说明。应用内更新检查读取 `/releases/latest`，只识别最新正式版本。
6. 将安装包复制到 `release/` 并提交文档变更（构建产物目录默认 gitignore，按仓库现状处理）。

## 代码签名（待接入）

需要一张 Windows 代码签名证书（OV/EV 或 Azure Trusted Signing）。证书和密码不得提交到仓库。

签名示例（证书就绪后，在构建步骤之后执行）：

```powershell
$env:TIDELINE_CERT_PATH = 'C:\secrets\tideline.pfx'
$env:TIDELINE_CERT_PASSWORD = '<从密钥管理系统注入>'
signtool sign `
  /fd SHA256 `
  /tr http://timestamp.digicert.com /td SHA256 `
  /f $env:TIDELINE_CERT_PATH /p $env:TIDELINE_CERT_PASSWORD `
  .\src-tauri\target\release\bundle\nsis\tideline_<版本>_x64-setup.exe

signtool verify /pa /v .\src-tauri\target\release\bundle\nsis\tideline_<版本>_x64-setup.exe
```

签名后重新计算 SHA256，并确认 SmartScreen 不再提示未知发布者。

## 自动安装的前置条件

要升级为「应用内下载并安装」，至少需要：

- 安装包与更新清单都带有可验证的签名；
- Tauri updater 公钥写入应用配置，私钥只存在于 CI/本地密钥库；
- 更新清单（`latest.json`）通过 HTTPS 提供，并与 GitHub Release 版本一致；
- 下载后校验签名/哈希，失败时保留旧版本并可回滚。

在上述条件满足前，`open_external` 只允许打开 `https://github.com/Lemostic/tideline` 下的发布页，
不会执行任何自动下载或安装。
