# 潮线 tideline 开发计划（V0.1–V0.3 及后续路线图）

> 本地优先、开源免费的多视图看板工具 —— 把任务放在你自己的电脑里。

---

## 一、项目定位

市面上的看板工具大致分两类：好用的要订阅（协作能力绑定云端），免费的要么限制看板数量、要么体验粗糙。**潮线（tideline）** 想解决的是另一类需求：**个人 / 小团队在单机上管理项目，不需要账号、不需要联网、数据完全属于自己。**

| 维度 | 潮线 tideline | 板栗看板（参考对象） | 通用 SaaS 看板 |
| --- | --- | --- | --- |
| 部署 | Windows 桌面端，单文件 SQLite | 飞书/网页，云端 | 云端 |
| 账号 | 不需要，打开即用 | 需要 | 需要 |
| 离线 | 完全可用 | 依赖网络 | 依赖网络 |
| 收费 | 开源免费，无功能墙 | 企业版付费 | 订阅制 |
| 数据 | 本机 `tideline.db`，复制即备份 | 平台持有 | 平台持有 |
| 协作 | 不做团队协作（本地个人工具的定位取舍） | 强 | 强 |

**核心取舍**：不做多人协作与云端同步，把「看板操作手感 + 本地数据可靠」打磨到可以每天用；数据模型、视图与交互都围绕单机个人使用设计。

## 二、V0.1 范围（本次交付）

### 2.1 目标

一个**可以真正用起来**的桌面看板：新建看板、增删改列表与任务、拖拽排序、按截止日期聚合任务、快速收集想法，数据持久化在本地 SQLite，重启不丢。

### 2.2 包含（In Scope）

| 模块 | 内容 |
| --- | --- |
| 应用外壳 | 侧边栏导航、顶栏、路由、全局搜索（Ctrl/Cmd+K）、任务详情抽屉、错误提示、启动加载 |
| 工作台 | 今日聚焦 / 目标进度 / 看板全景 / 最近更新 / 指标卡，新建看板、星标、重命名、删除 |
| 看板详情 | 看板标题与主题色、看板视图（Kanban）、列表增删改、任务增删改、原生拖拽跨列与重排、连续新增卡片、视图切换（看板可用，其余占位） |
| 我的任务 | 全部任务按「已逾期 / 今天到期 / 本周到期 / 稍后到期 / 无截止日期」分组、逾期计数、看板筛选、排序、隐藏已完成、点击打开任务抽屉 |
| 收件箱 | 快速记录（Ctrl/Cmd+Enter）、条目列表、转为任务（选择看板 + 列表）、删除 |
| 模板中心 | 模板分类筛选、模板预览、一键生成看板（含列表与卡片） |
| 数据层 | SQLite（Tauri）/ localStorage（浏览器开发态）双实现，接口一致 |
| 菜单占位 | 仪表盘 / 看板集 / 目标三个进阶菜单保留入口，展示清晰的路线图占位页；看板内表格 / 甘特 / 日历视图保留 Tab 与占位 |

### 2.3 不包含（Out of Scope，进入路线图）

- 日历视图（V0.3）；仪表盘、看板集、目标（V0.4–V0.5）
- 团队协作、账号、云同步、分享链接（产品定位不计划）
- 附件、自定义字段、自动化规则
- 自动更新、代码签名与安装包分发（V0.3+）

### 交互约定

- **任务详情统一入口**：看板卡片、表格行、甘特条、我的任务卡片、搜索结果都打开同一个全局抽屉（`TaskDrawer`），字段修改「失焦/点击即保存」，不做输入级防抖。
- **任务内容**：标题、描述（Markdown）、所属列表、状态、开始/截止日期、优先级、完成、标签、子任务与自动进度；不包含成员、评论、通知等协作字段。
- **新建看板**：创建后自动带「待办 / 进行中 / 已完成」三条列表，避免空白画布。
- **删除**：看板 / 列表删除前二次确认（硬删除并级联）；任务删除改为移入回收站，可恢复或彻底删除。
- **筛选**：看板内筛选条件跨看板/表格/甘特/日历四个视图保持，不写入数据库。
- **弹窗**：打开时聚焦第一个输入控件；后续输入重渲染不得抢焦点（V0.3 修复）。
- **首次启动**：写入一套演示数据（4 个看板 + 若干任务 + 3 条收件箱），让用户第一眼看到完整形态；清空后不再自动重播（`tideline.seeded` 标记）。

## 四、技术架构

### 4.1 选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 体积小（~10MB 级）、原生窗口、系统 WebView 复用，Rust 侧可直连 SQLite |
| 前端 | React 18 + TypeScript + Vite | 生态成熟、类型安全、构建快 |
| 状态 | Zustand | 轻量、无样板代码、快照式状态适合本地单用户 |
| 路由 | React Router（HashRouter） | Tauri 自定义协议下刷新/深链不 404 |
| 样式 | 手写 CSS + 设计令牌（无 UI 框架） | 完全掌控视觉，避免通用组件"AI 味"；离线无字体/图标网络依赖 |
| 数据 | SQLite（rusqlite，bundled） | 单文件、可复制备份、事务可靠、零外部服务 |
| 图标 | 内置线性 SVG 图标集 | 离线、风格统一 |

### 4.2 数据流

```
React 页面
  └─ Zustand store（snapshot 唯一数据源，写操作先落盘再更新内存）
       └─ src/lib/api.ts（TidelineApi）
            ├─ Tauri 环境：invoke(...) → Rust commands → SQLite
            └─ 浏览器环境：localStorage 快照（开发/预览降级，接口一致）
```

- 启动时 `getSnapshot()` 一次性拉取 boards / lists / cards / inbox（本地单用户、数据量小，避免 N+1 请求）。
- 写操作返回单条实体或 void，store 据此增量更新快照；删除操作在本地同步移除关联数据。
- 前端所有派生数据（某看板的列表、某列表的卡片、分组结果）用 `useMemo` 计算，选择器只返回稳定引用。

### 4.4 数据模型（SQLite）

```sql
boards(id TEXT PK, title TEXT, description TEXT, color TEXT,
       starred INTEGER, created_at TEXT, updated_at TEXT)

lists(id TEXT PK, board_id TEXT REFERENCES boards(id) ON DELETE CASCADE,
      title TEXT, position INTEGER, created_at TEXT)

cards(id TEXT PK, board_id TEXT REFERENCES boards(id) ON DELETE CASCADE,
      list_id TEXT REFERENCES lists(id) ON DELETE CASCADE,
      title TEXT, description TEXT, due_date TEXT NULL,
      start_date TEXT NULL, labels TEXT NOT NULL DEFAULT '[]',
      subtasks TEXT NOT NULL DEFAULT '[]', deleted_at TEXT NULL,
      priority TEXT NULL, completed INTEGER, position INTEGER,
      created_at TEXT, updated_at TEXT)

inbox_items(id TEXT PK, content TEXT, created_at TEXT)
```

- `start_date` / `due_date` 为 `YYYY-MM-DD` 纯日期，分别用于甘特排期与截止提醒。
- `labels` / `subtasks` 以 JSON 文本存储：`labels` 是字符串数组；`subtasks` 是 `{id,title,done}[]`，进度由完成数 / 总数派生，不额外存储。
- V0.2 迁移：启动时用 `PRAGMA table_info(cards)` 检查缺列并 `ALTER TABLE ADD COLUMN`（幂等，不重建表），完成后写入 `PRAGMA user_version = 2`。
- V0.3 迁移：新增 `deleted_at` 列与索引，`user_version = 3`；回收站任务为 `deleted_at IS NOT NULL`，快照只返回活动任务。
- V0.7 迁移：cards 增加 `accent`，lists 增加 `color` / `wip_limit`，`user_version = 7`；旧数据按默认值补齐。
- V0.8 迁移：新增 `team_members` / `overtime_records` / `performance_records` 三张表与索引，`user_version = 8`；旧库自动建表，空项目组。
- V0.9 迁移：新增 `projects` / `project_meta_fields` / `project_roles`，团队表补 `project_id` / `role_id`，加班/绩效补 `project_id`；旧 V0.8 团队数据自动建「默认项目 + 默认角色」归属，`user_version = 9`。
- V0.8.3 迁移：新增 `member_tenures` 表与索引；已有成员按 joined_at/released_at 自动补首段，`user_version = 10`。

- 时间统一 ISO-8601 字符串（`2026-10-30T00:00:00.000Z`），截止日期用纯日期 `YYYY-MM-DD` 按本地时区解读。
- `position` 为同一父级内的排序序号，写操作后重排，读取即按 `position` 升序。
- 索引：`lists(board_id)`、`cards(list_id)`、`cards(board_id)`、`cards(due_date)`、`inbox_items(created_at)`。

### 4.5 前后端接口契约（55 个命令）

所有写命令只有一个 `input` 参数；返回结构体 `serde(rename_all = "camelCase")`；错误以 `Result<T, String>` 透出。

| 命令 | input | 返回 | 语义要点 |
| --- | --- | --- | --- |
| `get_snapshot` | — | Snapshot | 启动全量加载 |
| `create_board` | `{title, description?, color?}` | Board | 标题 trim 兜底，时间戳写入 |
| `update_board` | `{id, patch}` | Board | 更新 updatedAt |
| `delete_board` | `{id}` | — | 级联删除列表与任务 |
| `create_list` | `{boardId, title}` | List | position 追加末尾 |
| `update_list` | `{id, patch}` | List | 标题 trim |
| `delete_list` | `{id}` | — | 级联删除任务，重排剩余 |
| `create_card` | `{boardId, listId, title, ...（含 startDate/labels/subtasks）}` | Card | position 追加末尾 |

## 五、设计规范

- **气质**：安静、留白、信息密度适中，接近纸质工作台；动效克制（120–190ms）。
- **主色**：潮线青 `#0f766e`；点缀暖沙 `#e9a23b`；背景 `#f3f5f2`；卡片纯白；描边 `#e7ebe5`。
- **字体**：系统字体栈（无网络字体），中文优先 PingFang / 微软雅黑。
- **圆角**：卡片 12–14px、按钮 8px、小标签 6px。
- **阴影**：两档轻阴影，禁止彩色大阴影与渐变滥用。
- **看板主题色**：8 色可选，用于看板封面/列表色条，不参与文字颜色。
- **文案**：中文、短句、动词开头；空状态给下一步动作，不写"暂无数据"。

## 七、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 前端 localStorage 与 Rust SQLite 行为漂移 | 浏览器验收通过但桌面端异常 | 接口契约唯一来源 `src/lib/api.ts`，Rust 侧单元测试覆盖同语义；每个版本做端到端冒烟 |
| 旧版本数据库升级失败 | 用户数据丢失 | 启动时按列存在性幂等迁移，不重建表；迁移失败给出可读错误并提示先备份；Rust 单测覆盖 V0.1 → V0.2 |
| 甘特视图拖拽与滚动冲突 | 改期误触 / 页面跳动 | Pointer Events + 位移阈值（>3px 才算拖拽）+ 按天吸附；Playwright 覆盖拖拽与点击区分 |
| Tauri 首次编译慢 / 环境差异 | 构建等待 | 依赖版本锁定，构建脚本标准化；CI 缓存 `~/.cargo` 与 `target` |
| 数据损坏 / 误删 | 用户数据丢失 | WAL + 事务；删除二次确认；V0.3 任务删除已进回收站；V0.4 增加导出备份 |
| 单文件 SQLite 被占用 | 备份/复制失败 | 文档说明先退出应用再复制；V0.4 增加「导出备份」入口 |
| 安装包分发 | 用户安装失败 / 签名告警 | NSIS 安装包已验证安装/卸载；V0.6 增加代码签名与自动更新 |
| 功能蔓延导致定位模糊 | 产品失焦 | 明确「个人本地工具」定位，团队协作类需求一律不做 |

## 八、开发与验证命令

```bash
pnpm install            # 安装依赖
pnpm dev                # 浏览器开发（127.0.0.1:5173，localStorage 数据）
pnpm typecheck          # tsc 全量类型检查
pnpm test               # vitest 单元测试
pnpm build              # 前端产物 dist/
pnpm tauri dev          # 桌面端开发（Tauri + Vite）
pnpm tauri build --bundles nsis   # Windows NSIS 安装包
```

- 桌面端数据库路径：`%APPDATA%/com.lemostic.tideline/tideline.db`（按 Tauri app_data_dir 规则）。
- 浏览器开发数据：localStorage key `tideline.db.v1`，清空该 key 可重置演示数据。
